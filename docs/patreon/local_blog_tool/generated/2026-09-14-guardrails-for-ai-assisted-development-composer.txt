TITLE: Building Guardrails for AI-Assisted Development
VISIBILITY: Members only

This draft is written for members, so it stays closer to the active build surface and assumes interest in the day-to-day engineering and editorial decisions behind Biblion.

Today’s focus is building guardrails for ai-assisted development, which sits at the intersection of the project’s public story and the practical work needed to keep the platform moving.

A new Developer workflow wizard, selective UI generator, Qt 6 strategy, PR evidence gate, and nomenclature guide turn project memory into enforceable practice.

The checklist became executable:

BiblionOCR now includes a Developer-only workflow wizard that guides a human contributor from scope and hypothesis through implementation, validation, risk review, and handoff. Nineteen evidence gates must be resolved before the wizard reports that a change is eligible for pull-request review.

The generated evidence is checked by repository automation. This does not replace human judgment; it makes the expected proof visible and harder to forget.

Reproducibility and migration:

UI and resource generation was centralized in a compare-before-replace tool, so unchanged generated files keep their timestamps and only real byte changes reach the worktree. A documented Qt 6 migration strategy provides a provisional PySide6 direction without forcing a premature framework conversion.

Finally, a project nomenclature guide now separates informal input from canonical committed output. It defines names and aliases while leaving semantic meaning to the design specification and implementation status to architectural evidence.
